# 09 · 테스트

> [!info] 위치
> `tests/archive_test.cpp` · Qt Test (`QTEST_APPLESS_MAIN` — 이벤트 루프 불필요)
> 코어만 검증 (`lmdbarchiver_core` + `Qt6::Test`). UI 테스트 없음.

## 🧪 시나리오 (8개)

### `roundTripDirectory`
- `자료/` 폴더(중첩 + 빈 폴더 + 한국어 파일명 + 128 KiB 바이너리) 추가 → 추출
- 항목 수 5, 내용·경로·디렉터리 시간(±2초) 일치 검증

### `replaceAndRemove`
- 같은 내부 경로에 두 번 추가 → 최신 내용(`two-two`)으로 교체 확인
- `removePaths({"docs"})` 로 하위까지 삭제, `recordCount(archive) == 0` (LMDB 레코드 0)

### `reopenArchive`
- 10 MiB 파일 스트리밍 추가 → 닫기 → 다시 열기 → 추출
- 블록별 내용(`a`~`j`)까지 정확히 일치하는지 검증 (한국어 파일명 `다시열기.lmdb`)

### `legacyCompatibility`
- **v1 레거시 아카이브를 직접 생성** (`createLegacyArchive` 헬퍼) → 열기 → 추출
- v2 코어가 v1 포맷을 읽고 풀 수 있음을 검증 → [[02·아카이브 포맷 v2#버전 호환성]]

### `transactionalCancellation`
- 파일 추가 중 **3번째 콜백에서 취소** → 트랜잭션 abort
- 이전 내용(`original`)이 그대로 보존되는지 추출로 확인
- 추출 중 취소 시 **기존 보호 파일**(`keep-me`)이 덮어씌워지지 않는지 확인
→ [[03·Archive 코어 API#트랜잭션과 취소]]

### `mapGrowth`
- 36 MiB 난수 파일 → map size 자동 성장 확인
- 재개장 후 항목 1개, 크기 정확 → [[02·아카이브 포맷 v2#map size 성장]]

### `clearArchive`
- 항목 추가 → `clear()` → 항목 0 + `recordCount == 0`

### `integrityVerification`
- 정상 아카이브 생성 → `verify()` 통과
- **`corruptFirstChunk` 헬퍼로 첫 청크의 마지막 바이트를 `^= 0x5A`** (비트 뒤집기)
- 손상 후 `verify()` 실패 + 오류 메시지 비어있지 않음 → [[03·Archive 코어 API#verify-검증]]

### `compactArchive`
- 두 개 36 MiB 파일 추가 → 하나 삭제 → `compact()`
- 파일 크기가 **감소**했는지(`after < before`)
- 정리 후에도 `verify()` 통과 + 남은 항목 정확 → [[03·Archive 코어 API#compact-페이지 회수]]

## 🔧 테스트 헬퍼 (익명 namespace)

| 헬퍼 | 역할 |
|---|---|
| `recordCount(path)` | LMDB를 직접 열어 `mdb_stat.ms_entries` 반환 — 레코드가 정말 삭제됐는지 확인 |
| `createLegacyArchive` | **v1 포맷** 아카이브를 손수 기록 (단일값, 압축) — 하위 호환 검증용 |
| `corruptFirstChunk` | `chunk:` 접두 키의 마지막 바이트 비트 플립 — 무결성 검증용 |

> [!note] `QTEST_APPLESS_MAIN`
> `QApplication` 없이 실행 → 코어가 순수 로직(이벤트 루프 불필요)임을 보여준다.

```powershell
# 또는: ctest --preset release
```
