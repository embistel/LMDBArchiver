# 02 · 아카이브 포맷 (Native)

> [!abstract]
> `.lmdb` 파일은 LMDB가 `MDB_NOSUBDIR` 모드로 여는 단일 파일이다. **키는 UTF-8 경로 문자열, 값은 원본 파일 바이트 그대로** — 헤더·래핑·압축·청크 분할이 전혀 없는 순수 스키마. LucioraEla 원 시스템, Python `lmdb`, C liblmdb 등 모든 표준 LMDB 도구가 투명하게 읽고 쓸 수 있다.

## 🔑 키/값 스킴

```
LMDB Key:   UTF-8 경로 문자열 (예: "Roi_0/Defect_000123.bmp")
LMDB Value: 원본 파일 바이트 그대로 (압축 X, 헤더 X, 청크 X)
```

- `cleanArchivePath`로 정규화된 경로(`/` 분리, 앞 `/` 제거, `QDir::cleanPath`, `..` 차단)가 키가 된다
- 값에는 어떤 메타데이터도 들어가지 않는다 — 파일의 원시 바이트만
- **이식성**: Qt가 없어도, 매직/플래그/길이 헤더를 몰라도 `mdb_get(key)` → 파일로 저장하면 원본이 복원된다

> [!warning] 키 길이 제한
> LMDB는 키 길이에 상한(`mdb_env_get_maxkeysize`)이 있다. 내부 경로가 너무 길면 `MDB_BAD_VALSIZE`로 거부한다. 압축 모드는 키가 13자(`.<8hex>.gz`) 더 길어진다.

---

## 🗜️ 선택적 gzip 압축 (메타데이터 없음)

압축도 value에 메타데이터를 전혀 넣지 않는다. 대신 **키의 접미사로 자기 서술**한다.

| 모드 | LMDB Key | LMDB Value |
|---|---|---|
| 비압축(기본) | `Filename.bmp` | 원본 파일 바이트 |
| 압축 | `Filename.bmp.<crc32>.gz` | 표준 gzip(RFC 1952) 바이트 |

- `<crc32>` = 논리 경로(`Filename.bmp`)의 UTF-8 바이트에 대한 CRC-32, **8자 소문자 hex** (miniz `mz_crc32`)
- 값은 [10바이트 헤더][raw deflate 본문][crc32 LE][isize LE] 구조의 **표준 gzip 스트림** → `gunzip`/7-zip/Python `gzip` 등 어떤 표준 도구로도 풀 수 있다
- 압축은 miniz 2.2.0(퍼블릭 도메인, `vendor/miniz/`에 정적 포함)의 `tdefl`/`tinfl`로 생성·해제

### 추출 시 압축 감지 (auto-decompress)

1. 키가 `^(.*)\.([0-9a-f]{8})\.gz$` 매치?
2. `crc32(utf8($1)) == $2` → **Archiver가 압축한 것** → value를 gunzip → `$1` 이름으로 저장
3. 매치 안 되거나 해시 불일치 → **진짜 사용자 `.gz` 파일** → 키 그대로, 값 그대로 저장

→ CRC-32 검증 덕분에 진짜 `.gz` 파일과 거짓 양성 구별이 사실상 불가능하다. 사용자의 `report.csv.gz`를 비압축으로 저장하면 안전하게 보존된다.

### 메타데이터 없이 얻는 정보
- **원본 크기**: gzip 트레일러의 ISIZE(마지막 4바이트 LE)에서 압축 해제 없이 읽음 → `entries()`가 압축률(크기/저장 크기)을 보고
- **수동 폴백**: `--no-decompress`로 추출하면 `Filename.bmp.<crc32>.gz` 파일이 나오고, 사용자가 직접 `gunzip`하면 된다

> [!note] 압축 토글
> - GUI: **아카이브 → 추가 시 gzip 압축** 체크 (QSettings에 저장)
> - CLI: `create`/`add`에 `--compress`, `extract`에 `--no-decompress` (기본은 자동 해제)
> - 혼합 아카이브 가능: 각 항목이 키로 자기 서술하므로 같은 저장소에 압축·비압축 항목이 섞여도 된다

## 📋 보존되는 정보 / 보존되지 않는 정보

Native 스키마는 순수 key→value이므로, 파일 바이트 자체에 부가 정보를 담을 수 없다.

| 정보 | 보존? | 비고 |
|---|---|---|
| 파일 내용 | ✅ | value = 원본 바이트 |
| 파일 경로 | ✅ | key = 정규화된 경로 |
| 파일 크기 | ✅ | value 길이로 산출 |
| 빈 디렉터리 | ❌ | 디렉터리 엔트리를 저장하지 않음 (LucioraEla와 동일) |
| 수정 시각 | ❌ | 메타데이터 저장 불가 |
| 권한 | ❌ | 메타데이터 저장 불가 |
| 무결성(SHA-256) | ❌ | 헤더가 없으므로 해시도 저장 불가 |

→ `ArchiveEntry` 구조체는 유지하되, `modified`/`permissions`는 기본값, `storedSize == originalSize`, `directory`는 **메모리 합성**으로 채운다.

---

## 🌳 가상 디렉터리 합성 — `entries()`

저장소에는 파일(leaf) 레코드만 있다. 트리뷰에 폴더 계층을 보여주기 위해 `entries()`가 **메모리에서 디렉터리 노드를 합성**한다:

```cpp
// "Roi_0/Sub/Defect_001.bmp" → {"Roi_0", "Roi_0/Sub"} 집합 생성
QSet<QString> ancestorDirectories(const QString &path);
```

합성된 디렉터리 엔트리는 `directory=true`, `originalSize=0`이며, 하위 파일 크기의 합을 표시용 originalSize로 채운다. 이 노드들은 **저장되지 않는다** — `entries()` 호출마다 다시 계산된다.

---

## ➕ 파일 추가 — `addPaths`

```cpp
// 디렉터리: 저장하지 않음 (진행률 콜백만 호출)
// 파일: readAll() → mdb_put(key=경로, value=원본바이트)
QByteArray contents = file.readAll();
MDB_val keyValue{경로}, valueValue{contents};
mdb_put(txn, dbi, &keyValue, &valueValue, 0);
```

- 같은 경로에 다시 추가하면 delete-then-put으로 덮어쓴다
- 파일 전체를 한 번에 읽는다 (Defect 이미지 = 수 KB~수백 KB에 적합)
- 모든 쓰기가 단일 트랜잭션 안에서 일어나므로 부분 추가가 발생하지 않는다

---

## 📤 파일 추출 — `extract`

```cpp
// 커서 순회하며 value 바이트를 파일로 직접 저장
const QByteArray contents(value.mv_data, value.mv_size);
file.write(contents);
```

- `QSaveFile`로 원자적 쓰기
- 수정 시각/권한 설정은 하지 않는다 (메타데이터가 없으므로)

---

## 🔍 검증 — `verify`

원본 바이트가 그대로 저장되므로, 무결성 검증은 **모든 value가 읽기 가능한지** 확인하는 것으로 충분하다. SHA-256 검증은 없다.

---

## 🗑️ 항목 삭제 — `removePaths`

```cpp
// 단일 키 mdb_del (청크 루프 없음)
MDB_val key{경로};
mdb_del(txn, dbi, &key, nullptr);
```

`entries()`로 파일 목록을 얻어 매칭되는 경로를 찾고, 각각을 단일 `mdb_del`로 지운다. 합성 디렉터리 노드는 삭제할 것이 없다.

## 📈 map size 성장

LMDB는 고정 map size를 사용한다. 이 프로젝트는 동적으로 확장:

```cpp
// open(): 초기 64 MiB, 기존 파일 크기 이상까지 2배씩
quint64 initialMapSize = 64ull * 1024 * 1024;
while (initialMapSize < existingSize) initialMapSize *= 2;

// addPaths(): 예상 입력 크기로 사전 확장
bool ensureCapacity(quint64 incomingBytes, QString *error) {
    // used + incoming + 32 MiB 여유가 필요; 부족하면 2배씩
}
```

→ [[09·테스트#mapGrowth]]에서 36 MiB 파일로 성장 검증.

## 🔐 경로 정규화 — `cleanArchivePath`

```cpp
QString cleanArchivePath(const QString &path) {
    // 1. / 정규화 + trim
    // 2. 선행 / 제거
    // 3. QDir::cleanPath
    // 4. ".." / "../..." → 빈 문자열 (거부)
}
```

이 결과가 키에 들어가므로 **경로 순회 공격(path traversal)**이 원천 차단된다. 추출 시에도 목적지 루트 하위인지 다시 검증한다. → [[03·Archive 코어 API#경로 안전성]]

## 🔗 외부 도구 호환성

이 스키마는 LucioraEla(`Roi_X/Defect_NNNNNN.bmp` → BMP 바이트)와 **바이트 단위로 동일**하다.

**Python `lmdb` 패키지로 읽기:**
```python
import lmdb
env = lmdb.open("wafer.lmdb", subdir=False, readonly=True, lock=False)
with env.begin() as txn:
    bmp_bytes = txn.get(b"Roi_0/Defect_000123.bmp")
    # → BMP 파일로 저장하면 끝
```

**C liblmdb로 읽기:**
```c
mdb_env_open(env, "wafer.lmdb", MDB_NOSUBDIR | MDB_RDONLY, 0664);
mdb_txn_begin(env, NULL, MDB_RDONLY, &txn);
mdb_get(txn, dbi, &key, &value);  // value.mv_data = 원본 바이트
```

→ [[09·테스트#lucioraElaCompatibility]]·[[09·테스트#rawSchemaRoundTrip]]에서 양방향 호환성 검증.
